## 1. Цель

Учебный сайт по командам Linux, устроенный как DevOps_QA и Security_QA (разделы, поиск с транслитом, темы, клавиатура), но вместо вопросов и ответов в нём карточки команд. Главное отличие, каждая команда и каждый скрипт разобраны по частям. Строка `tar -czvf backup.tar.gz /etc` разбирается на `tar`, `-c`, `-z`, `-v`, `-f`, `backup.tar.gz`, `/etc`, и у каждой части своё объяснение. Многострочный скрипт разбирается построчно, а внутри строки так же по частям. Спецсимволы оболочки (`|`, `>`, `2>&1`, `$()`, `*`, `~`, `&&`, `;`, кавычки) выделяются как отдельные части со своим объяснением.

Читатель, Еркебулан. Окружение, по которому проверяются команды, его учебная ВМ, Ubuntu Server ARM (aarch64) без графики, доступ по SSH `[допущение]`.

## 2. Части системы

- **Движок сайта**. Копия React + Vite приложения из `~/Desktop/Projects/Security_QA/Security_Interview` (поиск, транслит, синонимы, подсветка, темы, клавиатура). Голосовой поиск убираю `[допущение]`, для команд он бесполезен. Security_QA не меняется ни одним байтом, файлы только копируются.
- **Компонент разбора команды (новый)**. Показывает строку команды цветными частями, цвет по типу части (команда, опция, аргумент, путь, оператор оболочки, переменная). Наведение или нажатие на часть подсвечивает её объяснение в таблице под строкой. Ниже таблица «часть → что делает», затем «что вы увидите» (пример вывода) и «частые ошибки».
- **Компонент построчного разбора скрипта (новый)**. Скрипт показан с номерами строк, у каждой строки объяснение, строку можно раскрыть до разбора по частям тем же компонентом.
- **Справочник спецсимволов**. Отдельный раздел, где каждый символ оболочки разобран один раз. Из разборов команд на него ведут ссылки.
- **Исходники корпуса**. `content/NN-slug.json`, один файл на раздел.
- **Сборщик корпуса**. `scripts/build-corpus.mjs`, по образцу Security_QA. Дополнительно проверяет, что части разбора, склеенные через пробел, дают ровно исходную строку команды. Это механическая защита от разбора, который не совпадает с командой.
- **Проверка ссылок**. `scripts/check-links.mjs`, как в Security_QA.
- **Проверка команд на ВМ**. `scripts/run-on-vm.sh` прогоняет безопасные примеры по SSH на учебной ВМ и сохраняет реальный вывод. Им заполняется поле «что вы увидите», чтобы пример вывода был настоящим, а не придуманным. Опасные команды (`rm -rf`, `mkfs`, `dd`, изменение сети) помечены и не запускаются.
- **Тесты**. `corpus.test.ts` (целостность, склейка частей, наличие источника) и `search.test.ts` (транслит: «грэп» находит grep, «тар» находит tar).
- **Деплой**. GitHub Pages через GitHub Actions, плюс офлайн-файл одним HTML, как `Security_QA_offline.html`.

Источники только первичные. Man-страницы Ubuntu 24.04 (noble) на manpages.ubuntu.com, GNU Coreutils manual и Bash Reference Manual на gnu.org, документация Ubuntu Server на ubuntu.com, systemd на freedesktop.org. Объяснение каждой опции сверяется с man-страницей, опции, которых нет в man, не пишутся.

## 5. Сценарии

1. **Разбор команды.** Открыл раздел «Архивы» → карточка tar → навёл на `-z` → в таблице подсветилось «сжать через gzip» → ниже реальный вывод с ВМ → ссылка на man tar открывается.
2. **Поиск транслитом.** Нажал `/` → набрал «грэп рекурсивно» → первая карточка grep с примером `grep -rn`.
3. **Скрипт построчно.** Раздел «Bash-скрипты» → скрипт бэкапа из 12 строк → у каждой строки объяснение → раскрыл строку 5 → разбор по частям, `$(date +%F)` ведёт на справочник символа `$()`.
4. **Символ.** В разборе нажал на `2>&1` → перешёл в справочник, где разобраны `2`, `>`, `&`, `1` по отдельности.

## 6. Что НЕ делаем

- Интерактивный терминал в браузере. Практика идёт на своей ВМ.
- Тесты и квизы на запоминание `[допущение]`, можно добавить второй очередью.
- Команды под RHEL, CentOS, Arch. Только Ubuntu и общие GNU-утилиты, различия по дистрибутивам не описываем.
- Правки DevOps_QA и Security_QA.

## 7. Критерии готовности

- Сборщик собирает корпус без ошибок, склейка частей совпадает с `line` во всех примерах.
- Тесты, линт и сборка зелёные.
- `check-links.mjs` без мёртвых ссылок.
- Безопасные примеры прогнаны на ВМ, поле `output` взято из реального прогона.
- Сайт проверен в браузере на ПК и на ширине телефона, наведение и раскрытие строк работают.
- Выборочный факт-чек опций против man-страниц, находки закрыты.
