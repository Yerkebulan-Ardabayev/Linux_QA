# Формат контента Linux_QA

Один файл на раздел, `content/NN-slug.json`. Проверяет `node scripts/build-corpus.mjs`, он же собирает сайт. Файл, который не проходит сборщик, не принимается.

## Файл раздела

```json
{
  "category": "Навигация и файлы",
  "cards": [ ...карточки... ]
}
```

## Карточка

```json
{
  "slug": "ls",
  "cmd": "ls",
  "text": "ls: показать содержимое каталога",
  "summary": "<p>Что делает команда и когда она нужна, 1-2 абзаца HTML.</p>",
  "examples": [ ...примеры... ],
  "script": null,
  "mistakes": ["<p>Частая ошибка и как её избежать.</p>"],
  "sources": ["https://man7.org/linux/man-pages/man1/ls.1.html"]
}
```

- `slug` уникален во всём корпусе, латиница, цифры, дефис. Для карточек раздела 01 slug задан заранее списком ниже.
- `cmd` имя команды или символа, по нему ищут.
- `text` заголовок карточки, формат «команда: что делает».
- `examples` 1-4 примера. Карточка без примеров допустима только если заполнен `script`.
- `script` для многострочных скриптов, иначе `null`.
- `mistakes` 0-3 пункта.
- `sources` 1+ ссылок, только первичные источники (ниже).

## Пример

```json
{
  "line": "tar -czvf backup.tar.gz /etc",
  "d": "Упаковать каталог /etc в сжатый архив backup.tar.gz и показать каждый файл.",
  "parts": [
    { "t": "tar", "k": "cmd", "d": "Программа архивации." },
    { "t": "-czvf", "k": "opt", "d": "Четыре опции склеены в одну.", "sub": [
      { "t": "-", "k": "op", "d": "Начало коротких опций." },
      { "t": "c", "k": "opt", "d": "create, создать новый архив." },
      { "t": "z", "k": "opt", "d": "Сжать через gzip." },
      { "t": "v", "k": "opt", "d": "verbose, печатать имя каждого файла." },
      { "t": "f", "k": "opt", "d": "file, следующий аргумент это имя архива. Поэтому f стоит последней." }
    ]},
    { "t": "backup.tar.gz", "k": "arg", "d": "Имя архива. .tar значит архив, .gz значит сжат gzip." },
    { "t": "/etc", "k": "path", "d": "Что упаковать, абсолютный путь." }
  ],
  "run": "container",
  "setup": "",
  "output": ""
}
```

### Правило частей (проверяется механически)

Части `parts` идут слева направо и покрывают строку `line` целиком, без пропусков и перестановок. Между частями в строке допустимы только пробелы. Всё, что не пробел, обязано попасть в какую-то часть. Проверка: сборщик ищет `t` каждой части в `line` начиная с конца предыдущей, и текст между ними обязан быть пустым или из пробелов.

То же для `sub`, он покрывает `t` своей части целиком, здесь пробелов между кусками обычно нет.

**По символам.** Разбирать до уровня, где каждый значимый символ объяснён. Склеенные опции (`-czvf`, `-rn`, `-la`) раскладывать через `sub`. Спецсимволы оболочки (`|`, `>`, `>>`, `2>&1`, `&&`, `;`, `$()`, `*`, кавычки, `~`, `$VAR`) всегда отдельная часть с `k: "op"` или `k: "var"` и полем `ref` на карточку раздела 01. Составные куски вроде `backup-$(date +%F).tar.gz` раскладывать через `sub` до `$(`, `date`, `+%F`, `)`. Регулярные выражения и шаблоны awk/sed тоже раскладывать через `sub` по значимым символам (`^`, `.*`, `[0-9]+`, `\1`, `s/…/…/g`).

### Типы частей `k`

`cmd` команда, `sub` подкоманда (`apt install`, `systemctl restart`, `ip addr`), `opt` опция, `val` значение опции, `arg` аргумент, `path` путь, `op` оператор или спецсимвол оболочки, `var` переменная, `str` строка в кавычках, `pat` шаблон или регулярное выражение, `num` число, `kw` ключевое слово bash (`if`, `then`, `for`, `do`, `done`, `fi`, `case`, `function`, `local`, `return`), `cmt` комментарий.

### Поле `ref`

Только у частей, которые являются спецсимволом оболочки, значение из списка slug раздела 01. Пример `{ "t": "|", "k": "op", "d": "Передать вывод ls на вход grep.", "ref": "sym-pipe" }`. В `d` писать смысл символа именно в этой строке, а общее объяснение живёт в карточке раздела 01.

### Поля запуска

Вывод придумывать нельзя. Поле `output` всегда пустое, его заполнит скрипт реальным запуском в контейнере `ubuntu:24.04` (arm64, root, без systemd, без сети наружу не рассчитывать).

- `run`: `"container"`, пример детерминированно работает в чистом контейнере Ubuntu 24.04 после `setup` (пакеты из базового образа, плюс ставятся coreutils, procps, iproute2, file, tree, less, acl, sudo, cron, curl, dnsutils, iputils-ping, netcat-openbsd, openssh-client, rsync, zip, unzip, xz-utils, bzip2, lsof, psmisc, util-linux, gawk, bc, jq, strace). `"system"`, нужен настоящий хост (systemd, реальная сеть, диски, другие машины), не запускается. `"danger"`, разрушительная или меняющая систему команда (rm -rf, mkfs, dd, fdisk, iptables -F, reboot), не запускается, в интерфейсе будет предупреждение.
- `setup`: команды bash, которые подготовят окружение для `run: "container"` (создать файлы, каталоги, пользователей). Выполняются перед `line` в том же контейнере, в каталоге `/lab`. Пустая строка, если подготовка не нужна. Подготовку делать короткой и такой, чтобы вывод был осмысленным (например 5 строк лога для grep).
- `output`: пусто.

Свой пример с `run: "container"` можно и нужно проверить до сдачи, образ `linuxqa-lab` уже собран (`lab/Dockerfile`):

```bash
docker run --rm linuxqa-lab bash -c 'cd /lab; <setup>; <line>'
```

Если команда падает или вывод пустой и бессмысленный, поправить `setup` или перевести пример в `system`.

## Скрипт

```json
"script": {
  "name": "backup.sh",
  "d": "Что делает скрипт целиком.",
  "lines": [
    { "line": "#!/bin/bash", "d": "Шебанг, скрипт запускает bash.", "parts": [
      { "t": "#!", "k": "op", "d": "Шебанг.", "ref": "sym-shebang" },
      { "t": "/bin/bash", "k": "path", "d": "Интерпретатор." }
    ]},
    { "line": "", "d": "" },
    { "line": "set -euo pipefail", "d": "…", "parts": [ … ] }
  ],
  "run": "container",
  "setup": "",
  "args": "",
  "output": ""
}
```

У каждой непустой строки обязательны `d` и `parts` по тому же правилу покрытия. Пустая строка, `{ "line": "", "d": "" }`. Отступы в начале строки сохранять в `line` как есть, в части они не входят. `args` аргументы запуска скрипта.

## Источники

Только первичные, ссылка на конкретную страницу.

- Man-страницы, `https://man7.org/linux/man-pages/man1/<cmd>.1.html` (раздел 1, 5, 7, 8 по факту).
- Bash, `https://www.gnu.org/software/bash/manual/bash.html` с якорем раздела, например `#Pipelines`, `#Redirections`, `#Shell-Parameter-Expansion`.
- GNU Coreutils, `https://www.gnu.org/software/coreutils/manual/html_node/<page>.html`.
- GNU grep, sed, gawk, tar, findutils manuals на gnu.org.
- Ubuntu Server docs `https://documentation.ubuntu.com/server/...`, systemd `https://www.freedesktop.org/software/systemd/man/latest/<unit>.html`, OpenSSH `https://man.openbsd.org/<cmd>`.

Объяснение каждой опции должно совпадать с man-страницей. Опции, которой нет в man, нет в карточке. Ссылку ставить только ту, в существовании которой уверен.

## Стиль

Русский язык, обращение на «вы», коротко и буквально. Длинное тире не использовать, ставить запятую или точку. Двоеточие внутри фразы не ставить, только перед перечислением. Без жаргона («дёрнуть», «пингануть»). HTML в `summary` и `mistakes`: `<p>`, `<code>`, `<b>`, `<ul><li>`.
